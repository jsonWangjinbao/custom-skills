# 异常处理手册

注入、执行、收集阶段遇到异常时按需加载对应条目。

## 登录态

- Web 项目需要登录时：**先让用户在浏览器中完成登录**，再启动自动操作
- Browser 子代理执行中遇到登录页/鉴权跳转：暂停该步骤，请用户接管完成登录后继续
- 需要特定账号/角色权限才能触发的接口：在 Phase 1 步骤清单中标注，用户确认账号条件

## dev server 未就绪

- 执行前确认：入口 URL 可访问（curl 或浏览器打开）
- 未启动：提示用户启动 dev server 并告知端口，不要代用户做启动决策（端口/环境由用户定）

## IP 变更（RN 项目）

检测当前宿主机 IP：

```bash
ifconfig | grep "inet " | grep -v 127.0.0.1 | awk '{print $2}' | head -1
```

对比 `src/utils/claudeApiDebug.ts` 中硬编码的 ENDPOINT IP：

- 不一致 → 更新 claudeApiDebug.ts 的 ENDPOINT 为当前 IP，重启日志服务器，告知用户「IP 已变更为 X，已自动修复，请重新操作」
- Android 模拟器固定 `http://10.0.2.2:{PORT}`，不受宿主机 IP 影响

## 端口冲突

从 19999 开始，`lsof -i :{PORT}` 检查是否被占用，冲突则递减（19999 → 19998 → ...），不阻塞。

## 服务器启动失败

进程不存在时逐一排查：

1. 检查端口是否被占用 → 换端口（见「端口冲突」）
2. 检查 node 是否可用
3. 修复后验证：`curl -s http://localhost:{PORT}/health`
4. 告知用户修复了什么

## 日志为空分级诊断

`.log` 文件不存在或无内容时，按顺序排查：

1. 服务器是否存活：`curl -s http://localhost:{PORT}/health` → 挂了则重启并告知用户
2. ENDPOINT IP 是否与当前宿主机一致 → 见「IP 变更」
3. 端口是否被防火墙拦截（真机场景）
4. `apiDbg` 所在文件是否被热更新加载（确认 import 正确）；Web 项目可在浏览器 DevTools Network 面板搜索 `/log` 请求验证传输通道
5. 操作是否真的触发了接口（页面是否有请求发出 — 可让用户看 DevTools Network）
6. 直到日志产生，才能进入分析步骤

## 浏览器自动操作失败

Browser 子代理执行步骤失败时：

1. 元素找不到 → 截图确认页面实际状态（是否未加载完成/接口报错导致空白），等待后重试一次
2. 仍失败 → 换一种定位方式（文本 → 角色 → 坐标）再试一次
3. 页面报错/白屏 → 记录现象和截图，该步骤标记为「执行失败」，继续后续步骤（接口报错本身可能就是联调要发现的问题）
4. 阻塞性失败（登录页、入口打不开）→ 暂停整个执行，请用户接管或修复后从断点步骤继续

## 并发联调会话

`.claude/auto-api-debug/manifest.json` 已存在时，提示用户「当前有进行中的联调会话 (ID)，模块 {module}，是否继续使用？」

- 继续 → 沿用已有 DEBUG_ID，只清空日志文件并重启服务器
- 新建 → 递增 NNN 创建新会话
- 模块不同 → 提示用户先完成或清理旧会话，避免注入互相干扰

## 超时

超过 30 分钟用户未响应：不做任何操作，注入代码和日志保留供手动查看。

## 用户中途放弃联调

kill 服务器 + 根据 manifest.json 还原注入点 + 删除 `.claude/auto-api-debug/` 临时文件。
