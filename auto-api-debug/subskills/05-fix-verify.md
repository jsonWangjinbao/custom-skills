# Phase 5 - 修复、回归循环与最终清理

## 进入条件

- 用户已确认 Phase 4 报告中的前端修复方案
- 或 Phase 4 无需修复、用户确认「联调完成」（此路径跳过修复，直接执行最终清理）

## 任务：应用修复

1. **只修前端待修项**（少传参、字段名错误、取值层级错误等）；后端待改项只留在报告中，不动手
2. **保留注入日志**（apiDbg 调用不删除）— 用于回归验证
3. **重启日志服务器**：
   - kill 旧进程，清空旧日志
   - 重新启动 server.mjs
   - 更新 manifest.json 中 serverPid
4. 告知用户：
   - Web：「✅ 修复已应用，我将重新执行操作步骤回归验证」→ 回 [03-execute.md](03-execute.md)
   - RN：「✅ 修复已应用，请重新操作验证，完成后告诉我『操作完了』」→ 用户操作后回 [04-report.md](04-report.md)

## 任务：回归循环

- 修复 → 回 Phase 3/4 重新执行与比对 → 更新报告
- 仍有前端问题 → 用户确认后继续修
- 此循环可能进行多轮，直到用户确认「联调完成」「没问题了」

## 任务：最终清理

仅在用户确认联调完成后执行（「联调完成」「没问题了」「清理吧」等）：

1. **杀掉日志服务器**：`kill <PID>`
2. **清理注入代码**：
   - 根据 manifest.json 的 `before` 字段精确还原每个注入点（用 Edit 工具反向替换）
   - 删除 `src/utils/claudeApiDebug.ts`
   - 删除整个 `.claude/auto-api-debug/` 目录前，**先询问用户是否保留 report.md 和 inventory.json**（用户可能需要报告给后端）；保留则将这两个文件移到用户指定位置后再删目录
3. **验证清理**：`grep -r "apiDbg" src/` 确认无调试代码残留；确认临时文件已删除
4. 告知用户：「✅ 联调代码已清理，仅保留业务修复改动」

## 出口

- 清理完成 → 必须进入 [06-distill.md](06-distill.md)（不可跳过）
