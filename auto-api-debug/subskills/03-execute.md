# Phase 3 - 执行操作

## 进入条件

- Phase 2 注入完成、日志服务器已就绪
- Web 项目：用户已确认「开始执行」；RN 项目：跳过本阶段，用户手动操作后直接进入 [04-report.md](04-report.md)

## 任务（Web 项目）

1. **执行前置检查**：入口 URL 可访问（失败按 [../reference/troubleshooting.md](../reference/troubleshooting.md)「dev server 未就绪」处理）
2. **派 Browser 子代理**按确认的步骤清单逐条执行，任务描述中必须包含：
   - 完整的步骤清单（含每步预期触发的接口）
   - 入口 URL 和登录态说明（遇到登录页立即暂停返回，不要尝试猜测账号密码）
   - 每步要求：执行操作 → 等待页面响应 → 截图保存到 `.claude/auto-api-debug/shots/step-{N}.png`
   - 收集页面 console 报错（报错原文 + 出现步骤）
   - 记录每步执行结果：成功 / 失败及现象
   - 明确告知子代理：页面报错/白屏不要停下来修，记录现象后继续后续步骤（接口报错可能正是联调要发现的问题）
3. **子代理返回后核对**：每步是否有截图、是否有步骤失败
   - 步骤失败按 troubleshooting「浏览器自动操作失败」分级处理；阻塞性失败暂停并告知用户
4. **告知用户**：「✅ N 个步骤已执行完毕（成功 X / 失败 Y），开始分析日志」

## 任务（RN 项目）

- 不执行本阶段。Phase 2 输出步骤清单后等待用户手动操作，用户告知「操作完了」直接进入 [04-report.md](04-report.md)

## 出口

- 执行完成 → 进入 [04-report.md](04-report.md)
- 阻塞性失败 → 暂停，等用户处理后从断点步骤继续或直接进入 [04-report.md](04-report.md) 分析已有日志
