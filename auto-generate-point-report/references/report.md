# 周报生成与发布（进入阶段 4 时读取）

> 本节结构与硬规则已从两份标杆报告（飞书 docx `Gfr8dbPtNoMMYjxQdtIcS8chnDe` 周度多问题报告、`AZZPd1fw3oPX3qxmphWcx60Mn0b` 单问题专项剖析）内化到本文件与模板，链接可能受权限限制；执行时以本文件为准，不需要打开原文。

## 报告写作

默认输出 RUN_DIR/report.md，按主文件链接的模板填写：**一份文档内列出全部问题，每个问题都深挖到可执行粒度**，不把深挖拆到另一份文档。
六节固定：口径说明（含数据局限）→ 核心指标总览 → 问题清单 → 页面交互优化清单 → 埋点价值小结 → 数据质量与受限项。
整节点核心 KPI 由 kpi.json 取得（本机复用看板分析器计算），SLS 专项指标由 evidence.json 取得；报告注明两种范围，不互换分母。
每个问题固定六点：现象（双口径）→ 数据证据（六个下钻维度）→ 业务影响 → 根因归纳（直接/行为/系统三层）→ 建议（按消减量排序）→ 为什么只有埋点能看见。
正式书面语、平实陈述与关键数字：编号清单，每条一句结论加量级；必要表格辅助，不写心理活动、俏皮反问或术语排比。
选题以证据为准（通常 3–8 项）：没有值得行动的问题则明确「未发现有充分证据支持的高影响问题」，不凑数。

硬规则（缺一项即视为报告未完成）：
1. 根因必须下钻到 `api_code` + 报文原文关键句 + 占比（保留报文里的阈值、配额、日期等数值）；只写 `fail_reason`/`api_biz_fail` 一层不算下钻。表单层另给字段与字段组合占比。
2. 每个问题给双口径：动作维度异常率（并标注是否被重复提交放大）+ 单据维度异常率；两者不得互代。
3. 单据级必须给重试强度分布（单均/p50/p90/max）与提交密度（中位间隔，如「每 2.2 秒一次」）；TOP 单据逐单还原时间区间与窗口内结局。
4. 人员表固定 11 列（账号/总操作/失败/失败率/涉及单据/异常单据/单据异常率/活跃区间/高峰时段/主要失败原因/行为画像）；行为画像只写数据支持的结论。
5. 建议按预期消减量排序，能给量化收益就给（「消减 38.1% 的整块留空打回」「仅该账号一周即可减少 1,239 次无效请求」）；未经对照实验不承诺百分比降幅。
6. 数据局限先做分布判定再下结论：逐日事件量、归零小时（仅完整自然日）、峰值小时、覆盖率缺口；区分「业务低谷」与「上报中断」必须写清判据，不凭单日量级直接定性。
7. 复核路径必写：scope 指纹、computeRunId、口径版本与配置指纹、可复跑命令与底稿文件名。
8. 配图位由人工补（页面/报文/看板单据明细截图）；无图则删掉占位行，不得用文字描述冒充截图，也不得自行生成示意图。
9. 隐私：账号以 ID 为准，姓名/组织名仅作展示且不据此认定自然人；IP 一律脱敏（IPv4 保留前三段、IPv6 保留 /64），不写完整地址；不公开手机号与大载荷原文。
10. 比率最多保留小数点后 4 位（本地一次遍历与看板流式累加存在 1 ULP 末位差，不得写成数据不一致）；并列计数项按 count 降序 + 名称二次排序后引用。
11. 均值远大于中位时必须同时给出两者并说明长尾；不得只报均值。
12. 协议状态码必须紧邻写作 `HTTP 200`（不写「HTTP 全部 200」），否则 report-check 会把 200 当数据数字要求溯源。
13. 任务链结局中 unknown 不等于异常（`chain_summary` 不参与聚合时尤其如此）；未闭环不等于卡死，必须标注窗口边界。

表格「人员」统一写「账号」，行为画像依据账号实际事件模式；IP 仅补网络来源线索且脱敏。
页面交互优化清单按页面分组，每条附数据证据与主要根因；末尾做共性归类（前置校验缺失 / 状态按钮未置灰 / 接口语义不诚实 / 长任务同步等待）并指出投入产出比最高的方向。
校验字段命中可以说「三个字段共同触发校验」，无 details/值证据不能说「三字段留空」；报文未披露阈值时不得自行推算配额。

## 数据质量与发布门禁

先执行 check，写完 report.md 后必须再执行 report-check（结构/根因深度/隐私/精度/数字溯源五类机械门禁），两者都通过才算可交付：
- 片段失败/损坏、条件不匹配、重复事件载荷冲突、无法去重、坏时间/范围错配 → 不发完整周报。
- 缺少单据关联、结果、原因、字典版本等 → 报告写覆盖率与受限项；不编造缺失指标。
- 没有数据 → 报告检查范围/保留期/版本/上报情况，不说业务一切正常。
- kpi.json 必须 complete、business ready、时间覆盖无缝铺满固定窗口，componentStatus 已声明 compare/pageStats/jsErrors 为 unsupported；核心指标与 SLS 明细是两次独立拉取，事件数不必相等，不得声称总量一致。
- 即便通过，说明观察边界、查询水位、computeRunId/configFingerprint/analyzerVersion/analyzerDigest，并声明核心指标由本地计算产出（未经看板服务与数据库）；采集端完整性未独立验证，当前版本不做跨窗对比。

质检清单：
1. 日期、环境、应用/页面与用户确认一致，未把样本指标套为全站指标。
2. 动作分母含成功，异常单据与涉及单据是独立集合；接口失败与表单打回分开。
3. 时间线是同类型单据，成功晚于失败才算恢复；闭环/一次通过/返工/卡单引用 kpi.json，不能用局部成功重算。
4. 每项结论有 actionKey + 证据 key；待验证根因和采集缺口显式列出。
5. 不公开密钥、手机号、大载荷、完整 IP 或原始数据库。

## 可选飞书交付

只有用户明确要求写飞书/给定目标文档时才执行外部写入。所有飞书操作只经 lark-cli。
先读 `lark-cli docs +update --help` 和对应 XML/Markdown guide，核对当前 CLI 参数，不照抄旧 positional 语法。
- 新周报：创建独立文档；更新：先 fetch 目标窄范围 with-ids，只替换授权段落，不覆盖其他业务材料。
- 原生表格文本可窄 str_replace；HTML 降级或含图片表格用 block_replace，保留图片与附件。
- 表头、正文与列表**水平居左**；按 CLI 当前 XML guide 的合法对齐属性设置，不猜标签。
- 写入后 fetch 复核标题、表头、样本数、段落和对齐；失败/部分写入如实报告。
- 不自动上传 fetch.checkpoints/ 或 evidence.sqlite；正文 IP 脱敏。

## 交付回执

只说目标/窗口/环境、发现数量、两三项最有价值结论、产物链接和验证限制。
示例：「已生成发货单节点报告（明确日期，prod），核心指标由本机复用看板分析器计算（computeRunId 与口径版本已记录），列 4 项问题并逐题深挖到 api_code 与单据级重试密度，附页面交互优化清单；缺失字段与不可用维度已单列。」
